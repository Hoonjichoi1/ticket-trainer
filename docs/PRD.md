# 티케팅 연습 시뮬레이터 MVP PRD

## 🎯 핵심 정보

**목적**: 실제 콘서트 예매를 연습장으로 쓰는 피해를 막기 위해, 진짜 좌석 경합과 장애 상황을 재현한 안전한 티케팅 훈련 환경을 제공한다.
**사용자**: 대형 아이돌 콘서트 티케팅을 앞두고 실전처럼 연습하고 싶은 한국 팬덤 사용자.

> UI/UX 기준: NOL(인터파크) 티켓의 플로우 문법을 따르되(대기열 → 좌석 → 결제, 순번 표시, 정각 버튼 활성화), 로고·브랜드 등 시각 정체성은 자체 디자인을 사용한다. 특정 플랫폼 UI 복제는 하지 않는다. 단, 예매 가능 좌석은 보라색으로 표시한다 — 한국 티케팅 문화에서 남은 좌석을 "포도알"이라 부르는 관례의 재현으로, 공통 문법 리얼리즘의 일부다.

## 🚶 사용자 여정

```
1. 홈 (시작 페이지)
   ↓ 팬덤 규모(소/중/메가) 선택
   ↓ 오픈 정각까지 대기 → 새로고침 시 "예매하기" 버튼 활성화

2. 대기열 페이지
   ↓ 순번/예상 대기시간 실시간 갱신 (줄어드는 속도는 티어별 입장 속도가 결정)
   ↓ [새로고침/이탈] → 순번 리셋 (경고 문구 상시 노출)
   ↓ 내 차례 도달 → 입장 토큰 발급 → 자동 이동

3. 좌석 선택 페이지 (입장 토큰 필수 — 없으면 대기열로 리디렉션)
   ↓ 좌석맵에서 available 좌석 클릭
   [성공] → 좌석 hold (5분 타이머 시작) → 다음 단계
   [실패: 봇/타 사용자 선점] → "이미 선택된 좌석입니다" → 다른 좌석 재시도
   ↓

4. 예매 정보 페이지 (hold 타이머 계속 진행)
   ↓ 매수(1매 고정) · 수령 방법 선택 · 약관 동의 체크
   ↓ "결제하기" 클릭

5. 결제 페이지 (모의 결제창)
   ↓ 결제 수단 선택 (간편결제 / 카드 / 무통장입금 — 수단별 소요 시간 상이)
   [성공] → 예매 확정 → 결과 리포트
   [실패: 타임아웃/서버 에러 확률 주입] → 사용자 판단 분기:
      · 결제창 닫고 재결제 → hold 유지, 재시도 가능
      · 페이지 새로고침/뒤로가기 → hold 상실, 좌석 시장 방출 → 결과 리포트(실패)
      · hold 5분 만료 → 좌석 자동 해제 → 결과 리포트(실패)

6. 결과 리포트 페이지
   ↓ 성공/실패 + 단계별 소요 시간 + 경합에서 밀린 횟수 + 실패 시 판단 피드백
   ↓ [다시 도전] → 홈으로
```

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F001** | 팬덤 규모 선택 | 소/중/메가 티어 선택 → 대기열 길이·봇 강도·에러율·지연 계수 결정 | 난이도 조절이 훈련 서비스의 기본 가치 | 홈 |
| **F002** | 오픈 대기 경험 | 오픈 정각 전 버튼 비활성 → 정각 이후 새로고침 시 "예매하기" 활성화 | 실제 티케팅의 시작 관례 재현 (NOL/예스24 방식) | 홈 |
| **F003** | 대기열 순번 표시 | 진입 시 순번 부여, 순번·예상 시간 실시간 갱신. 순번 감소 속도는 티어별 입장 속도가 결정. 이탈/새로고침 시 순번 리셋 | 실제 티케팅의 심리적 압박 핵심 요소 | 대기열 페이지 |
| **F004** | 입장 토큰 검증 | 순번 도달 시 토큰 발급, 토큰 없이 좌석 선택 페이지 접근 시 대기열로 차단 | 대기열 우회(새치기) 방지 | 대기열 페이지, 좌석 선택 페이지 |
| **F005** | 좌석맵 표시 | 콘서트 seed 데이터의 좌석 배치(구역/행/열)를 기반으로 렌더링 (기본 seed 200석). 상태 3색 구분: available 보라("포도알") / held 구분색 / sold 회색. 실시간 갱신 | 경합 상황을 실시간으로 보여주는 훈련 화면 | 좌석 선택 페이지 |
| **F006** | 좌석 선점(hold) 경합 | 좌석 클릭 시 DB 트랜잭션 락으로 원자적 선점. 동시 클릭 시 1명만 성공, 나머지는 선점 실패 안내 | 서비스의 코어 — 진짜 경합이 유일한 차별점 | 좌석 선택 페이지 |
| **F007** | hold 5분 만료 | 선점 후 5분 내 결제 미완료 시 좌석 자동 해제(다음 조회 시점 lazy 처리) | 실제 티케팅 관례 + 취켓팅 상황 재현 | 좌석 선택 페이지, 예매 정보 페이지, 결제 페이지 |
| **F008** | 경쟁 봇 | 서버가 사용자와 동일한 hold 로직으로 랜덤 좌석을 선점. 티어별 강도 조절 | 혼자 연습이 아닌 실제 경쟁 상황 조성 | 좌석 선택 페이지 |
| **F009** | 결제 실패 주입 | 모의 결제 시 티어별 확률로 타임아웃/서버 에러 발생 | 실패 상황 훈련이 세 번째 차별점 | 결제 페이지 |
| **F010** | 실패 대응 분기 | 에러 후 사용자의 실제 행동(재결제/새로고침/이탈)에 따라 hold 유지·상실이 실제처럼 갈림 | "어떤 행동이 hold를 죽이는지" 판단 훈련 | 결제 페이지 |
| **F011** | 결과 리포트 | 성공/실패, 단계별 소요 시간, 경합 패배 횟수 표시. 피드백은 규칙 기반 — 판단 이벤트(에러 후 새로고침, 재시도 성공, hold 만료 등)를 정해진 코칭 문구에 매핑하고, 소요 시간·패배 횟수는 티어별 기준치와 비교 | 훈련의 학습 루프 완성 | 결과 리포트 페이지 |

### 2. MVP 필수 지원 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F012** | 익명 세션 | 쿠키 UUID로 사용자 식별 (회원가입/로그인 없음) | 대기열 순번·hold 소유자 식별에 필요한 최소 인증 | 전 페이지 (화면 없음) |
| **F013** | 예매 정보 입력 | 매수(1매 고정) 표시, 수령 방법 선택, 약관 동의 체크 | 실제 flow의 시간 마찰 재현 (실전 전이) | 예매 정보 페이지 |
| **F014** | 결제 수단 선택 | 간편결제 / 카드(더미 번호 입력 폼) / 무통장입금 중 선택. 수단별 모의 소요 시간 상이 (무통장 최속, 카드 최저속) | hold 잔여 시간에 따른 수단 선택 판단 훈련 | 결제 페이지 |

### 3. MVP 이후 기능 (제외)

- 회원가입/로그인 (익명 세션으로 대체)
- 보안문자 입력 (Sprint 여유 시 스트레치 골, 기본은 v2)
- 플랫폼 스킨 모드 (멜론/예스24 스타일 전환)
- 다좌석 예매 (2매 이상의 원자적 hold — v2 기술 스트레치)
- 가상 아이돌/공연 랜덤 생성, 여러 공연·좌석 등급
- 랭킹/기록 비교, 모바일 최적화, 실제 결제 연동, Redis 대기열, 실제 봇 트래픽 부하(Real Load)

## 📱 메뉴 구조

선형 훈련 플로우 서비스로, 일반 웹앱식 내비게이션 대신 단계 진행 구조를 사용한다.

```
📱 티케팅 시뮬레이터 진행 구조
├── 🏠 홈 (진입점)
│   └── 기능: F001 (팬덤 규모 선택), F002 (오픈 대기 경험)
├── ⏳ 대기열 페이지 (자동 진입)
│   └── 기능: F003 (순번 표시), F004 (입장 토큰 발급)
├── 💺 좌석 선택 페이지 (토큰 검증 후 진입)
│   └── 기능: F004 (토큰 검증), F005 (좌석맵), F006 (좌석 선점), F007 (hold 만료), F008 (경쟁 봇)
├── 📝 예매 정보 페이지 (hold 성공 후 진입)
│   └── 기능: F013 (예매 정보 입력), F007 (hold 만료)
├── 💳 결제 페이지 (약관 동의 후 진입)
│   └── 기능: F014 (결제 수단 선택), F009 (실패 주입), F010 (실패 대응 분기), F007 (hold 만료)
└── 📊 결과 리포트 페이지 (성공/실패 확정 시 진입)
    └── 기능: F011 (결과 리포트) → [다시 도전] 시 홈으로

🔧 공통 (모든 페이지)
└── F012 (익명 세션 — UI 없음, 쿠키 자동 발급)
```

## 📄 페이지별 상세 기능

### 홈

> **구현 기능:** `F001`, `F002` | **메뉴 위치:** 진입점

| 항목 | 내용 |
|------|------|
| **역할** | 훈련 시작점. 난이도를 정하고 실제 티케팅의 "오픈 대기" 순간을 재현 |
| **진입 경로** | 서비스 최초 접속, 결과 리포트에서 [다시 도전] |
| **사용자 행동** | 팬덤 규모 선택 → 오픈 시각까지 대기 → 정각 이후 새로고침해 예매하기 클릭 |
| **주요 기능** | • 팬덤 규모 3티어 선택 카드 (각 티어의 난이도 설명 포함)<br>• 가상 콘서트 정보 표시 (자체 창작 콘서트 1개)<br>• 오픈 카운트다운 + 정각 전 비활성 버튼<br>• **예매하기** 버튼 (새로고침 시 활성화) |
| **다음 이동** | 예매하기 클릭 → 대기열 페이지 |

| 항목 | 내용 |
|------|------|
| **역할** | 실제 티케팅 대기열의 순번 압박 재현 + 입장 통제 |
| **진입 경로** | 홈에서 예매하기 클릭, 토큰 없이 좌석 선택 페이지 접근 시 리디렉션 |
| **사용자 행동** | 순번이 줄어드는 것을 지켜보며 대기 (새로고침 유혹을 참는 훈련) |
| **주요 기능** | • 내 순번 + 앞 대기 인원 + 예상 시간 표시 (2초 폴링)<br>• "새로고침 시 순번이 초기화됩니다" 상시 경고<br>• 새로고침/이탈 시 실제로 순번 리셋<br>• 순번 도달 시 입장 토큰 자동 발급 |
| **다음 이동** | 토큰 발급 → 좌석 선택 페이지 자동 이동 |

> **구현 기능:** `F004`, `F005`, `F006`, `F007`, `F008` | **진입 조건:** 유효한 입장 토큰

| 항목 | 내용 |
|------|------|
| **역할** | 서비스의 코어. 봇·타 사용자와의 실시간 좌석 경합 |
| **진입 경로** | 대기열에서 토큰 발급 후 자동 이동 (토큰 없으면 대기열로 차단) |
| **사용자 행동** | 사라져가는 좌석 중 available 좌석을 빠르게 클릭해 선점 시도, 실패 시 즉시 다른 좌석 재시도 |
| **주요 기능** | • 200석 좌석맵 3색 상태 표시, 2초 폴링 갱신<br>• 좌석 클릭 → 선점 성공/실패 즉시 피드백 ("이미 선택된 좌석입니다")<br>• 봇이 실시간으로 좌석을 가져가는 경합 상황<br>• 선점 성공 시 5분 hold 타이머 시작<br>• **좌석 선택 완료** 버튼 |
| **다음 이동** | 선점 성공 + 완료 클릭 → 예매 정보 페이지 |

### 예매 정보 페이지

> **구현 기능:** `F013`, `F007` | **진입 조건:** 좌석 hold 보유

| 항목 | 내용 |
|------|------|
| **역할** | 실제 flow의 마찰 단계 재현 — hold 타이머가 흐르는 중의 시간 압박 |

| **주요 기능** | • 선택 좌석 + 남은 hold 시간 상시 표시<br>• 매수 1매 고정 표시<br>• 수령 방법 선택 (모바일 티켓/현장 수령 — 모의)<br>• 약관 동의 체크박스<br>• **결제하기** 버튼 (전체 동의 시 활성화) |

### 결제 페이지

> **구현 기능:** `F014`, `F009`, `F010`, `F007` | **진입 조건:** 예매 정보 완료

| 항목 | 내용 |
|------|------|
| **역할** | 실패 상황 훈련의 핵심 — 에러 발생 시 올바른 판단 학습 + 잔여 시간 대비 수단 선택 |
| **진입 경로** | 예매 정보 페이지에서 결제하기 클릭 (별도 결제창/모달 형태) |
| **사용자 행동** | 남은 hold 시간을 보고 결제 수단을 선택해 모의 결제 진행. 에러 발생 시 재결제/새로고침/이탈 중 스스로 판단 |
| **주요 기능** | • 결제 수단 선택 (간편결제 / 카드 더미 입력 폼 / 무통장입금 — 수단별 소요 시간 상이)<br>• 모의 결제창 (남은 hold 시간 표시)<br>• 티어별 확률로 타임아웃/서버 에러 발생 (실제처럼 불친절한 에러 화면)<br>• 결제창 닫고 재결제 → hold 유지<br>• 페이지 새로고침/뒤로가기 → hold 실제 상실, 좌석 방출<br>• **결제 완료** 처리 (성공 시) |
| **다음 이동** | 성공 → 결과 리포트(성공) / hold 상실·만료 → 결과 리포트(실패) |

### 결과 리포트 페이지

> **구현 기능:** `F011` | **진입 조건:** 예매 성공 또는 실패 확정

| 항목 | 내용 |
|------|------|
| **역할** | 훈련 결과 분석과 판단 피드백 — 학습 루프의 완성 |
| **진입 경로** | 결제 성공, hold 상실/만료, 세션 실패 확정 시 자동 이동 |
| **사용자 행동** | 자신의 기록과 판단을 복기하고 재도전 여부 결정 |
| **주요 기능** | • 성공/실패 결과 표시<br>• 단계별 소요 시간 타임라인 (대기열/좌석/정보 입력/결제)<br>• 경합에서 밀린 횟수 (선점 실패 카운트)<br>• 실패 시 원인 + 올바른 대응 피드백 (예: "새로고침으로 hold 상실 → 결제창만 닫고 재시도했어야 함")<br>• **다시 도전** 버튼 |
